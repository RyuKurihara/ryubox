# 用語の「処理イメージ」仕様（content/visual/<cat>.json）

各用語について「見た目・計算・実装」で理解できるようにするための追加データ。JSON配列。

```json
{
  "id": "d3-space-coding",                 // 既存の terms/<cat>.json の id（必須・一致させる）
  "steps": [                               // 処理イメージ。入力→処理→出力を具体的に、3〜6手順
    "① プロジェクタから白黒の縞（ビット0：左半分白/右半分黒）を投影して撮影",
    "② 縞を細かくしながら（1/2→1/4→…）n枚撮影。各画素で白=1/黒=0 を読む",
    "③ n枚分のビット列（グレイコード）→ 10進数に変換すると、その画素に当たった光が『プロジェクタの何列目か』が分かる",
    "④ カメラの画素位置とプロジェクタの列番号で三角測量 → 奥行き"
  ],
  "example": "具体的な数値例（任意）。例: 3ビットで8列。ある画素の観測が 白,黒,白 → グレイコード 101 → 2進 110 → 列6",
  "figures": [ { "type": "svg", "svg": "<svg viewBox='0 0 300 160' xmlns='http://www.w3.org/2000/svg'>…</svg>", "caption": "…" } ],
  "code": "import cv2\nimport numpy as np\n# 日本語コメントで、何をしているか分かるように\n..."
}
```

## figures
問題と同じ型: `svg` / `grid`（{"type":"grid","data":[[...]],"max":255,"values":true}、2値は max:1 で 1=黒）/ `matrix` / `table`。
- **見た目が想像できること**が最優先。可能なら「入力画像 → 処理 → 出力画像」を横に並べた図にする（グリッドの数値例や、SVGで描いた簡単な画像）。
- SVG はシングルクォート属性、viewBox 幅 240〜340、文字 font-size 9〜13、背景は白前提。日本語ラベル可。
- 1用語あたり図は1〜2個。

## code
- 試験は選択式だが、理解のための実装。Python + NumPy（必要なら OpenCV: cv2）で 6〜30 行。
- できるだけ「アルゴリズムの中身が見える」書き方（cv2の関数1行で終わる場合は、NumPyでの素朴な実装も併記）。
- 法律・歴史・概念のみの用語（知財など）は code を省略し、steps と figures（関係図・判断フローチャート・事例図）を厚くする。

## steps / example
- 抽象語だけで済ませない。数値・画素値・座標など**具体例**で書く。
- 「何が入力で、何が出力で、出力はどう見えるか」を必ず書く。
